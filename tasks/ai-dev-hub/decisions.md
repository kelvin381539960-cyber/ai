# AI Dev Hub 决策记录

## Decision 001：不自研完整 IDE

状态：已决定。

原因：

- IDE 成本过高，包括编辑器、LSP、Git、终端、调试、插件生态、跨平台等。
- 当前核心痛点不是编辑器，而是任务、上下文、交接和工具切换。
- 第一版应避免陷入 UI 和编辑器 API 细节。

结论：

- 不做完整 IDE。
- 做 AI 开发任务中台。

## Decision 002：第一版只接 Cursor CLI

状态：已决定。

原因：

- 用户已有 Cursor CLI 在腾讯云服务器上的使用习惯。
- 单一执行器能降低 MVP 复杂度。
- 先把一个工具管理好，再扩展多个工具。

结论：

- MVP 执行器只接 Cursor CLI。
- 后续再加 Codex CLI / Claude Code / API adapter。

## Decision 003：部署在腾讯云服务器

状态：已决定。

原因：

- 用户上班用公司电脑，下班用个人电脑。
- 云服务器可以作为统一 AI 工作现场。
- Cursor CLI 已在腾讯云服务器上。

结论：

- AI Dev Hub 第一部署目标是腾讯云服务器。
- 公司电脑和个人电脑只作为访问终端。

## Decision 004：第一阶段先做 CLI，不做 UI

状态：建议。

原因：

- CLI 能最快验证核心流程。
- UI 过早会增加实现成本。
- 先把任务、上下文、日志、handoff 跑通。

结论：

- 阶段 1 实现 CLI 原型。
- 阶段 3 再做 Web UI。

## Decision 005：Web UI 不直接公网暴露

状态：建议。

原因：

- 中台会访问代码、密钥、执行命令。
- 公网裸露风险高。

结论：

- 通过 SSH tunnel、VPN、Tailscale、WireGuard 或 Cloudflare Zero Trust 访问。

## Decision 006：记忆系统必须可控

状态：建议。

原因：

- 系统可以越用越懂用户，但不能黑盒记忆。
- 用户需要能查看、编辑、删除记忆。

结论：

- 重要记忆必须用户确认后写入。
- 用户偏好、项目规则、技术决策分开管理。
