# AI Work Hub 用户可用性评估

## 1. 评估结论

按“真实用户明天就要使用”的标准评估，当前 BRD/PRD 方向正确，但还不能直接进入实现后就保证可用。

当前状态：

```text
产品方向：正确
核心闭环：基本完整
用户路径：基本顺
真实可用性：仍有缺口
```

主要风险不是大功能缺失，而是一些“使用时才发现没有”的基础能力还没写清楚。

如果不补，可能出现：

- 用户创建了任务，但不知道下一步点哪里。
- 添加了资料，但助手没有正确引用。
- 生成了输出，但不能编辑、复制、改版本。
- 外部 AI 输出无法方便粘贴回来。
- 流程跑到一半无法暂停/继续。
- 多电脑使用时不知道数据存在哪里。
- 默认模板不够完整，第一次打开像空壳。

## 2. 总体评分

当前方案可用性评分：

```text
75 / 100
```

补齐本评估中的 P0 和 P1 后，预计可到：

```text
88 - 92 / 100
```

## 3. P0：不上线就不能用的缺口

## 3.1 缺少“首次启动/初始化向导”

### 问题

当前 PRD 有首页和任务创建，但没有首次使用流程。

真实用户第一次打开时需要知道：

- 数据存哪里。
- 是否需要登录。
- 是否本机/服务器运行。
- 是否已有默认助手。
- 是否已有默认流程。

### 必须补

首次启动向导：

```text
Step 1：选择数据目录
Step 2：创建第一个 Workspace
Step 3：安装默认助手模板
Step 4：安装默认流程模板
Step 5：进入首页
```

### 验收

用户第一次打开后，不需要手动配置 Agent/Workflow，也能直接开始一个任务。

## 3.2 缺少默认模板种子数据

### 问题

PRD 有模板名称，但没有明确系统初始化必须内置模板。

如果没有默认模板，用户第一天使用会发现：

```text
没有助手
没有流程
不知道怎么开始
```

### 必须补

初始化时必须安装：

默认助手：

```text
调研助手
PRD 助手
竞品分析助手
运营方案助手
数据分析助手
会议纪要助手
评审助手
技术追问助手
```

默认流程：

```text
需求调研流程
PRD 生成流程
竞品分析流程
运营活动流程
会议纪要流程
评审流程
数据复盘流程
技术追问流程
```

默认任务入口：

```text
做需求调研
写 PRD
做竞品分析
做运营方案
整理会议纪要
做评审
做数据复盘
技术追问
自定义任务
```

### 验收

用户不创建任何自定义助手，也可以完成一次调研任务。

## 3.3 缺少 Manual Assistant 的完整交互

### 问题

产品定位依赖用户把 prompt 复制给外部 AI，再把结果粘贴回来。

但 PRD 没有细化：

- prompt 怎么展示。
- 复制按钮在哪。
- 粘贴结果后保存到哪里。
- 是否可以继续下一步。
- 如果用户关闭页面怎么恢复。

### 必须补

Manual Assistant Run 页面必须支持：

```text
展示生成的 prompt
一键复制 prompt
显示当前 run 状态 waiting_user
粘贴外部 AI 输出
保存为 Output
继续 workflow 下一步
关闭页面后可恢复 pending run
```

### 验收

用户可以用 ChatGPT/Claude/Cursor Chat 完成一次 Manual Run，并把结果保存回任务。

## 3.4 缺少 Output 编辑和版本管理

### 问题

PRD 有 Output，但没有明确输出是否可编辑。

真实使用中，产品/运营一定会：

- 修改 AI 输出。
- 合并多个版本。
- 标记最终版。
- 复制给别人。

### 必须补

Output 必须支持：

```text
编辑内容
保存新版本
标记最终版
复制 Markdown
转为资料
基于输出创建新任务
```

### 验收

用户可以把 AI 生成的 PRD 草稿改成自己的版本，并标记为最终版。

## 3.5 缺少资料引用规则

### 问题

Material 是核心对象，但目前没有明确助手运行时怎么选资料。

可能导致：

- 用户添加了资料，但系统没用。
- 系统用了太多资料，token 失控。
- 用户不知道本次用了哪些资料。

### 必须补

每次运行前必须显示“本次使用资料”：

```text
使用全部标准资料
仅使用重点资料
手动选择资料
使用最近新增资料
```

资料可标记：

```text
重点资料
普通资料
暂不使用
```

### 验收

用户在运行助手前能确认本次会引用哪些资料。

## 3.6 缺少 Workflow 暂停/继续机制

### 问题

PRD 提到 waiting_user，但没有完整说明 workflow run 如何暂停和继续。

真实场景中用户会中断：

- 等外部 AI 输出。
- 去补资料。
- 明天再继续。

### 必须补

Workflow Run 必须支持：

```text
暂停
继续
取消
查看当前步骤
查看下一步
补充资料后继续
从 waiting_user 恢复
```

### 验收

用户今天运行到一半，明天打开任务仍能继续。

## 3.7 缺少本地/服务器部署的使用边界

### 问题

用户实际会在公司电脑和个人电脑使用。

当前 PRD 没说明：

- 数据放服务器还是本地。
- UI 怎么访问。
- 文件上传放哪里。
- 多电脑是否看到同一份数据。

### 必须补

MVP 部署默认：

```text
运行在私有服务器
浏览器访问 UI
数据存服务器 SQLite / 文件目录
上传资料存服务器 workspace
公司电脑和个人电脑访问同一服务器
```

### 验收

用户换电脑后能看到同一任务、资料、输出和执行记录。

## 4. P1：不补会明显影响体验的缺口

## 4.1 缺少“下一步建议”机制

### 问题

任务详情页如果只展示资料和输出，用户可能不知道下一步该做什么。

### 建议补

每个任务显示下一步建议：

```text
添加资料
继续生成
找评审助手看看
生成最终结论
创建后续任务
```

### 验收

用户打开任务详情页后，能看到明确下一步动作。

## 4.2 缺少任务完成标准

### 问题

产品/运营任务什么时候算完成？

### 建议补

任务完成条件：

```text
至少有一个最终 Output
用户手动标记完成
可选填写完成备注
```

### 验收

用户可以把任务从进行中标记为完成，并保留最终输出。

## 4.3 缺少输出导出能力

### 问题

用户生成 PRD、纪要、方案后，必然要复制或导出。

### 建议补

Output 支持：

```text
复制 Markdown
复制纯文本
导出 .md
后续导出 .docx
```

MVP 至少支持复制 Markdown。

## 4.4 缺少搜索和筛选

### 问题

多任务、多资料、多输出后，必须搜索。

### 建议补

MVP 至少支持：

```text
任务搜索
资料搜索
输出搜索
按任务类型筛选
按状态筛选
```

## 4.5 缺少错误和空状态设计

### 问题

真实使用必然遇到空状态和失败。

### 建议补

必须设计：

```text
没有任务
没有资料
没有输出
助手运行失败
外部结果未回填
流程中断
```

每个空状态都要有下一步按钮。

## 4.6 缺少草稿保存

### 问题

用户创建任务、编辑输出时可能中途离开。

### 建议补

支持：

```text
任务创建草稿
Output 编辑草稿
资料编辑草稿
```

MVP 至少支持 Output 编辑不丢失。

## 4.7 缺少任务资料隐私提示

### 问题

产品/运营会放用户反馈、业务数据、会议纪要。

### 建议补

添加提示：

```text
资料将保存在你的私有服务器。
复制到外部 AI 前，请确认不包含敏感信息。
```

Manual Assistant 复制 prompt 前也应提示。

## 5. P2：后续增强，不影响首次使用

## 5.1 输出模板自定义

后续支持用户自定义 PRD 模板、会议纪要模板、运营方案模板。

## 5.2 批量资料导入

后续支持批量上传文件、批量粘贴用户反馈。

## 5.3 外部 AI Action / MCP

后续支持 ChatGPT Action / MCP 管理任务。

## 5.4 权限和多用户

后续支持团队协作。

## 5.5 成本统计

后续支持统计 token 和工具使用成本。

## 6. 推荐补充到 PRD 的最小清单

为了确保实现后能直接给用户使用，PRD 还必须补充以下内容：

```text
onboarding.md            首次启动/初始化向导
seed-templates.md        默认助手和流程模板
manual-run-flow.md       手动助手复制/回填流程
output-rules.md          输出编辑、版本、导出规则
material-rules.md        资料选择、重点资料、引用规则
workflow-run-rules.md    流程暂停、继续、恢复规则
```

不一定都拆文件，但这些内容必须进入技术方案前明确。

## 7. 是否能直接实现后给用户用

当前 PRD 如果直接实现，能做出核心产品，但可能出现使用断点。

判断：

```text
不能直接保证好用。
需要补 P0 缺口后再进入技术方案。
```

必须先补：

```text
首次启动向导
默认模板种子数据
Manual Assistant 完整回填流程
Output 编辑/版本规则
Material 引用规则
Workflow 暂停/继续规则
部署和多电脑访问边界
```

补完后才适合进入技术方案。

## 8. 最终结论

当前方案不是不能用，而是还缺“真实使用闭环”的细节。

如果目标是避免上线后发现“这没有、那没有”，必须先补 P0。

一句话：

```text
产品主线已对，真实可用性还要补齐初始化、模板、回填、资料、输出、恢复这六个关键环节。
```
