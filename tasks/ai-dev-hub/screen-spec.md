# AI Dev Hub UI 页面方案

## 1. UI 原则

第一版 UI 不是 IDE，不承载代码编辑能力。

它只做任务驾驶舱：

- 看任务。
- 看上下文。
- 触发执行。
- 看日志。
- 看 diff。
- 看 handoff。

## 2. 信息架构

Web UI 第一版包含 6 个页面：

1. 项目页。
2. 任务列表页。
3. 任务详情页。
4. 执行日志页。
5. Diff / Review 页。
6. 设置页。

## 3. 项目页

### 3.1 目标

管理服务器上的项目工作区。

### 3.2 核心信息

- 项目名称。
- 项目路径。
- Git 分支。
- Git 状态。
- 当前活跃任务。
- 最近执行时间。

### 3.3 操作

- 添加项目。
- 进入项目。
- 刷新 git 状态。
- 打开终端提示命令。

## 4. 任务列表页

### 4.1 目标

查看所有任务状态。

### 4.2 字段

- 任务标题。
- 状态。
- 推荐执行器。
- 最近执行时间。
- 是否有未提交 diff。
- 是否有 handoff。

### 4.3 操作

- 新建任务。
- 筛选状态。
- 查看任务详情。
- 归档任务。

## 5. 任务详情页

### 5.1 目标

承载单个任务的主要操作。

### 5.2 区块

#### 任务说明

显示：

- 目标。
- 范围。
- 不做什么。
- 验收标准。

#### 当前上下文

显示：

- 项目规则。
- 当前 handoff。
- 当前 git 状态。
- 常用命令。

#### 执行面板

按钮：

- 生成上下文。
- 用 Cursor CLI 执行。
- 生成 handoff。
- 生成 review prompt。
- 标记完成。

#### 风险提示

显示：

- 是否有未提交文件。
- 是否在 main 分支。
- 是否有敏感文件变更。
- 是否有测试失败。

## 6. 执行日志页

### 6.1 目标

复盘每一次 AI 执行。

### 6.2 字段

- run_id。
- agent。
- task。
- 开始时间。
- 结束时间。
- exit_code。
- stdout。
- stderr。
- 执行前 git status。
- 执行后 git status。

### 6.3 操作

- 复制 prompt。
- 复制日志。
- 基于该日志生成 handoff。

## 7. Diff / Review 页

### 7.1 目标

让用户在不打开完整 IDE 的情况下了解 AI 改了什么。

### 7.2 显示

- 文件变更列表。
- 变更摘要。
- 高风险文件提示。
- Review prompt。

### 7.3 操作

- 刷新 diff。
- 生成 review prompt。
- 复制给 Codex / Claude。

第一版可以只显示 `git diff --stat` 和完整文本 diff，不需要复杂 diff viewer。

## 8. 设置页

### 8.1 Agent 设置

- Cursor CLI 路径。
- 默认工作目录。
- 超时时间。

### 8.2 安全设置

- 是否允许在 main 分支执行。
- 是否允许自动 commit。
- 是否允许自动 push。
- 敏感文件黑名单。

MVP 默认：

- 不允许自动 push。
- 不允许自动 merge。
- 不允许自动 deploy。

### 8.3 用户偏好

- 默认先计划再执行。
- 默认小步修改。
- 默认生成 handoff。
- 默认 review 只看高风险问题。

## 10. UI 上线顺序

先做：

1. 任务列表。
2. 任务详情。
3. 执行日志。
4. Handoff 查看。

后做：

1. Diff viewer。
2. 设置页。
3. 记忆管理。
4. 多工具 dashboard。
