# AI Work Hub 用户体验优化方案

## 1. 优化结论

根据最新反馈，方案需要从“工具管理视角”调整为“完成任务视角”。

旧路径：

```text
创建 Agent → 创建 Workflow → 创建 Task → Run → Handoff
```

新路径：

```text
选择任务类型 → 填写目标 → 添加资料 → 系统推荐助手和流程 → 开始执行 → 查看输出 → 继续优化 / 评审 → 生成最终结论
```

核心原则：

```text
用户不是来管理 Agent 和 Workflow 的，用户是来完成调研、PRD、运营方案、评审、总结等工作的。
```

## 2. 新产品定位

AI Work Hub 是面向产品经理、运营、技术型 PM 和个人开发者的 AI 工作任务台。

它帮助用户：

- 把一个工作任务持续推进到结果。
- 沉淀任务资料。
- 复用 AI 助手。
- 复用任务流程。
- 保存每次 AI 输出。
- 生成任务结论和交接说明。

## 3. 用户主路径

### 3.1 首页主入口

首页不从 Agent / Workflow 开始。

首页应该问：

```text
你想完成什么？
```

默认任务入口：

```text
做需求调研
写 PRD
做竞品分析
做运营方案
整理会议纪要
做评审
做数据复盘
技术追问
自定义任务
```

### 3.2 创建任务

任务创建只问核心问题：

```text
1. 你要做什么？
2. 这是哪类任务？
3. 有哪些资料？
4. 想要什么输出？
```

系统自动推荐：

- 默认助手。
- 推荐流程。
- 资料范围。
- 输出类型。

### 3.3 任务执行

任务详情页重点展示：

- 任务目标。
- 任务资料。
- 默认助手。
- 当前流程。
- 当前输出。
- 下一步动作。

主要操作：

```text
继续生成
添加资料
找其他助手看看
更换默认助手
生成最终结论
```

## 4. 用户可见对象命名

底层对象可以保留技术命名，但 UI 必须用用户语言。

| 底层对象 | UI 名称 |
|---|---|
| Task | 任务 |
| Agent | 助手 |
| Primary Agent | 默认助手 |
| Supporting Agent | 其他助手 |
| Workflow | 任务流程 |
| Run | 执行记录 |
| Handoff | 任务结论 / 交接说明 |
| Context Mode | 资料范围 |
| Source / Material | 任务资料 |
| Output | 输出结果 |

## 5. 新核心对象优先级

用户视角对象优先级：

```text
任务
任务资料
助手
任务流程
输出结果

```

底层仍保留：

```text

```

## 6. 必须新增 Source / Material

产品/运营任务的核心输入不是代码，而是资料。

必须支持任务资料：

```text
文本
链接
文件
截图
会议纪要
用户反馈
竞品资料
历史结论
外部 AI 输出
```

任务资料用于：

- 调研。
- PRD。
- 竞品分析。
- 运营方案。
- 评审。
- 总结。

## 7. 必须新增 Output

Handoff 不应是唯一产物。

产品/运营更关心输出结果：

```text
调研结论
PRD 草稿
竞品分析报告
运营方案
会议纪要
评审意见
下一步行动项
交接说明
```

因此 Handoff 应作为 Output 的一种。

Output 类型：

```text
research_report
prd_draft
competitive_analysis
ops_plan
meeting_summary
review_result
action_items
handoff
custom
```

## 8. 助手与流程的定位

助手和流程不是产品定位，而是帮助任务完成的能力组件。

### 助手

UI 应展示为“角色”：

```text
调研助手
PRD 助手
运营方案助手
竞品分析助手
数据分析助手
会议纪要助手
评审助手
技术追问助手
```

不应要求普通用户理解 Adapter。

### 任务流程

UI 应展示为“步骤向导”：

```text
步骤 1：确认目标
步骤 2：添加资料
步骤 3：生成初稿
步骤 4：评审优化
步骤 5：生成最终结论
```

不应做成复杂流程图。

## 9. 默认助手策略

Primary Agent 策略保留，但 UI 叫“默认助手”。

规则：

```text
一个任务默认由一个默认助手持续推进。
用户可以随时找其他助手看看。
用户可以随时更换默认助手。
```

更换时系统记录原因，并建议生成交接说明。

## 10. 资料范围策略

Context Mode 在 UI 中叫“资料范围”。

选项：

```text
简洁：只使用任务目标和最新结论。
标准：使用任务目标、任务资料和最近输出。
完整：使用全部资料、历史记录和相关文件。
```

默认：标准。

目标：控制 token，避免每次传全量上下文。

## 13. 导航优化

推荐主导航：

```text
首页
任务
资料
助手
流程
输出
设置
```

不推荐主导航直接放：

```text
Run
Handoff
CLI

```

这些放到任务详情或高级设置中。

## 14. 开发能力降级为高级能力

Git / Diff / CLI / Code Agent 不删除，但不作为默认入口。

它们放到：

```text
开发者模式
高级 Agent
高级资料类型
高级执行器
```

## 15. 优化后的核心闭环

```text
选任务类型
→ 填目标
→ 加资料
→ 系统推荐默认助手和任务流程
→ 点击开始
→ 查看输出
→ 添加资料或找其他助手评审
→ 生成最终结论 / 交接说明
```

## 16. 成功标准

优化后的 MVP 应能证明：

1. 产品/运营用户不需要先创建 Agent 才能开始。
2. 用户可以从任务类型直接开始。
3. 系统能自动推荐默认助手和流程。
4. 用户可以在任务中添加资料。
5. 用户可以持续生成输出。
6. 用户可以找其他助手评审。
7. 用户可以生成最终结论。
8. Run 和 Handoff 仍被记录，但不干扰主流程。

## 17. 关键结论

AI Work Hub 不应做成“AI 工具管理器”。

应该做成：

```text
产品经理 / 运营的 AI 工作台
```

用户看到的是任务、资料、输出和下一步。

系统内部再管理 Agent、Workflow、Run、Handoff、Context 和 Adapter。
