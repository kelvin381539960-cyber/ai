# AI Dev Hub 产品说明

## 1. 产品目标

AI Dev Hub 是一个本地/私有部署的 AI 开发任务中台，目标是让用户在多个 AI 编程工具之间切换时，任务状态、上下文、执行记录和交接信息不断裂。

核心目标：

> AI 工具可以换，但任务现场不能丢。

## 2. 目标用户

第一目标用户：

- 个人开发者。
- 同时使用 Cursor、Codex、Claude Code、API 的开发者。
- 上班用公司电脑、下班用个人电脑，需要统一远程开发环境的用户。

后续目标用户：

- 小型研发团队。
- 需要把 AI 编程流程标准化的团队。
- 有私有代码安全要求的团队。

## 3. 核心痛点

### 3.1 工具多，工作流不统一

用户可能同时使用：

- Cursor。
- Cursor CLI。
- Codex CLI。
- Claude Code。
- 公司 API。

每个工具有自己的上下文、聊天记录、额度和交互方式。

### 3.2 切换工具时上下文断裂

一个工具做到一半，额度不足或不适合继续时，换另一个工具需要重新解释：

- 项目背景。
- 当前任务。
- 已完成工作。
- 修改过的文件。
- 剩余问题。
- 下一步动作。

### 3.3 过程没有沉淀为项目资产

AI 的很多思考和操作散落在聊天记录中，没有沉淀到仓库中，后续难以复盘和接力。

### 3.4 多电脑工作现场不一致

用户上班使用公司电脑，下班使用个人电脑。如果 AI 开发环境和任务状态在本地，切换设备会造成上下文和环境割裂。

## 4. 产品形态

MVP 采用：

- 腾讯云服务器部署。
- 本地/私有 Web UI。
- CLI 管理命令。
- Cursor CLI 作为第一执行器。
- Git 仓库中的 `tasks/` 文档作为长期任务资产。

后续可扩展：

- Codex CLI adapter。
- Claude Code adapter。
- 公司 API adapter。
- VS Code / Cursor 插件。
- 桌面 App。

## 5. 核心模块

### 5.1 任务模块

负责创建、拆解、查看、归档任务。

字段建议：

- task_id。
- title。
- goal。
- scope。
- non_goals。
- acceptance_criteria。
- status。
- owner_agent。
- created_at。
- updated_at。

### 5.2 上下文模块

负责统一生成给 AI 工具的上下文，包括：

- 项目背景。
- 当前任务。
- 技术约束。
- 已有决策。
- 当前 git diff。
- 最近执行日志。

### 5.3 执行模块

负责调用 Cursor CLI 或其他执行器。

第一版只需要支持：

- 选择项目。
- 选择任务。
- 生成 prompt。
- 调用 Cursor CLI。
- 记录 stdout/stderr。
- 记录开始/结束时间。
- 记录退出状态。

### 5.4 交接模块

负责生成 `handoff.md`。

必须记录：

- 已完成。
- 已修改文件。
- 已执行命令。
- 测试结果。
- 当前风险。
- 剩余问题。
- 下一步建议。

### 5.5 Review 模块

负责基于 git diff 生成 review prompt，供 Codex / Claude / Cursor 审查。

### 5.6 成本模块

第一版不需要精准计费，只记录：

- 使用了哪个工具。
- 任务耗时。
- 执行次数。
- 人工标注效果。

后续再接入 API 计费和额度阈值。

## 6. MVP 页面

本地 Web UI 页面建议：

1. 项目列表。
2. 任务列表。
3. 当前任务详情。
4. Agent 执行面板。
5. 日志面板。
6. Git diff 面板。
7. Handoff 面板。
8. 设置页面。

## 7. 成功标准

MVP 成功标准：

- 可以在服务器上创建任务。
- 可以生成标准 AI 上下文。
- 可以调用 Cursor CLI 执行任务。
- 可以保存执行日志。
- 可以生成 handoff。
- 用户换电脑后能继续同一个任务。
- 用户换 AI 工具时无需重新解释完整背景。

## 8. 北极星指标

跨工具接续成功率。

更具体：

> 一个任务从 Cursor CLI 切到另一个 AI 工具时，是否能基于 handoff 和上下文继续执行，而不需要用户重新解释项目背景。
